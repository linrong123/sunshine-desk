# 已安装官方版主机的可回滚试用方案

本文是可回滚试用的通用步骤，实际执行结果另见[部署记录](DEPLOYMENT.md)。执行前应核对会话中的既有授权是否明确覆盖具体服务切换；已有具体授权时不重复确认。对每台主机仍需只读预检安装版本、服务属性、配置路径及兼容性，不能直接复用其他主机的运行数据。

试用前必须具备可靠的管理或本地控制入口，并验证能够在串流不可用时恢复。首次预检曾遇到命令环境无法启动、来宾执行未获开放；连接能够接通也不能证明命令或回滚可执行。后续部署前已重新验证 SSH 命令入口，不依赖禁用的来宾执行。不能将“已保存连接配置”当作“可用的回滚通道”，也不能把连接重置直接判定为网络根因。不要通过本方案顺带扩展网络排查、修改网络设置、解除限制或绕过禁用的来宾执行。

## 为什么使用 ZIP

现有 MSI 产品身份、服务名和默认安装位置沿用 Sunshine。试用应优先把 CI ZIP 解压到独立目录，保留官方二进制和配置，通过临时更改既有 SCM 服务的 ImagePath 切换版本。不要用 MSI 覆盖原安装，不要卸载官方版，不要在试用中重装显示或输入驱动。

源码证据：

- `tools/sunshinesvc.cpp` 固定服务名为 `SunshineService`。服务入口用相同名字注册，不能直接把它当作第二个 `DeskService` 并行运行。
- 服务包装程序从自身路径去掉文件名和最后一级目录，并将结果设为工作目录，再启动相对名称 `Sunshine.exe`，不转发普通命令行配置参数。
- ZIP 必须保留“试用根目录 / sunshine.exe”和“试用根目录 / tools / sunshinesvc.exe”的层次。不能只复制包装程序、把目录拍平，或试图给服务路径追加配置文件参数来重定向子进程配置。
- `src/platform/windows/misc.cpp` 的 `appdata()` 返回 Sunshine.exe 同目录下的 `config`。`src/config.cpp` 中默认读取其 `sunshine.conf`，相对证书/状态路径由 `path_f()` 锚定该 config 目录；默认不在服务账户的个人 AppData 下。

## 可审查步骤

1. **只读预检。** 记录真实主机上既有服务的原 ImagePath、运行账户、启动类型、恢复设置、当前状态、官方版本和实际配置位置。保存原属性的私有回执，不能只凭默认安装位置推断。确认本地或备用管理入口可靠可用。
2. **准备独立文件。** 校验指定 CI 提交和 ZIP 哈希，在本机管理员保护的短路径中解压完整目录；不要放在普通用户可替换文件的下载或共享目录。本次 ZIP 实际包含 Sunshine/ 顶层目录，应将其内部含 sunshine.exe 的目录作为试用根，不能误用解压输出的上一级。确认 Sunshine.exe、tools/sunshinesvc.exe、assets 和运行依赖完整。原安装目录保持不动。
3. **核对授权范围和试用窗口。** 对照已有会话授权，确认其是否明确覆盖指定试用包、服务路径切换、预计串流中断和回滚步骤；已有具体授权时直接沿授权执行，不重复确认。仅在这些动作未获授权或范围存在实质歧义时，展示具体差异并补齐必要确认。备用管理入口预检失败时，应先恢复并证明回滚通道可用，再执行切换。
4. **制作一致备份和私有副本。** 授权范围明确且回滚入口可用后，确认没有活跃串流，正常停止原服务，再备份原配置及必要私有外部文件，复制到独立试用 config。原文件不移动、不改写。不盲目复制原 `display_device.state` 恢复快照，应在原服务正常退出并确认显示已恢复后，让试用版本建立自身显示状态。
5. **审查副本。** 检查试用配置的 `pkey`、`cert`、`file_state`、`credentials_file`、`file_apps`、`log_path` 和全局准备命令。相对路径应落到试用 config；绝对路径不能继续写回原安装。将需要保留的私有外部文件复制到受保护的试用目录并仅修改副本路径。已有明确的显示设置会继续覆盖新默认值；若试验 auto，必须明确审查副本中的显示选项，不能假定旧 disabled 自动变成 ensure_active。
6. **临时切换。** 只将现有 `SunshineService` 的 ImagePath 改为试用根下 `tools/sunshinesvc.exe`，保持运行账户、启动方式、恢复设置等其他服务属性，随后启动。不要运行 ZIP 自带的安装/卸载服务脚本，它们还会停止或删除服务、改启动类型并立即启动。
7. **验证有效路径。** 先确认 SCM 包装程序与实际 Sunshine 子进程都来自试用目录，再核验管理页面、客户端配对、Desktop-only、客户端协商分辨率、远端光标显隐和断线恢复。确认原安装配置未被写入，观察显示和输入驱动状态。任何失败均先保留私有诊断结果，再回滚，不延长未批准的试用范围。
8. **回滚。** 正常停止试用服务，观察显示恢复；将 ImagePath 恢复为原值并启动原服务，核验原二进制路径、原配置、原配对及桌面显示。必要时按预先记录恢复其他服务属性。不要把试用配置反向覆盖原目录，不因一次失败卸载原版本或重装驱动。保留试用目录供排查，待另行确认后再清理。

## 配对是否必须迁移

不迁移也能运行：空试用 config 会走首次账户设置与重新配对。但它会拥有新的主机身份，既有客户端可能需要重新配对，不能承诺直接无感重连。

若希望保持原身份，必须一起私有复制主机证书和私钥、带 `uniqueid` 及已配对客户端记录的状态文件，以及单独指定的管理账户 `credentials_file`（若有）。默认凭据位于 config/credentials，默认状态文件为 sunshine_state.json，管理凭据默认沿用状态文件。只复制 sunshine.conf 或 apps.json 不足以迁移配对。

依据为 `src/config.cpp` 的默认路径与路径解析、`src/nvhttp.cpp` 的状态加载和证书校验，以及 `src/httpcommon.cpp` 的证书和管理账户加载。旧官方版本的实际格式和自定义路径仍需实机预检；保留备份不等于已经证明兼容或可恢复。

私钥、配对状态和账户文件只在该主机受保护位置保存，不进入仓库、公共工件、截图或公开日志。试用期间新增的配对默认只存在试用副本；回滚不会自动同步回原版本。

## 不能忽略的边界

- 包装程序复制 LocalSystem 令牌到当前控制台会话，试用目录必须避免普通用户写入；路径也应避免 MAX_PATH 限制。
- 固定服务名及端口不能支持官方版与试用版同时监听。停止和切换会中断串流；必须先确认已有授权覆盖切换，并具备可靠的备用管理入口。
- 服务包装层仍使用系统临时目录下的 sunshine.log 并轮转，因此“原配置不动”不等于整台机器零写入。
- 显示配置状态位于新 config 下的 display_device.state；启动/退出可能应用或恢复系统显示模式。正常停止会尝试恢复，异常退出或失联情况下的恢复不能只靠文件备份保证。
- 此方案不改控制台会话迁移，不绕过锁屏，不自动安装 VDD，不代替真实机的双端功能验收。
